## What actually runs

The native C/C++ diagnostic executes two original, unpatched recompiled functions:

| Original function | Observation |
| --- | --- |
| `0x80000400`, 64 bytes | Clears exactly `0x800A0600..0x801AFD80`, sets `sp=0x800CEC50`, dispatches to `0x800007B8` |
| `0x80000500`, 352 bytes | Chooses the original three buffer pointers based on configuration byte `+0x12` |

8 MiB of word-aligned RDRAM is initially filled with sentinels. The diagnostic verifies the complete cleared interval and every byte outside it before the buffer-profile checks. The observed continuation is a deliberate stop before OS/game initialization. Any unexpected continuation fails; there are no pretend-success guest OS services.

The buffer-profile test supplies a controlled original-game configuration pointer and flag, then executes the original function. The standard flag chooses `0x80307800`, `0x8032D000`, `0x80281D40`; the expanded flag chooses `0x80500000`, `0x80596000`, `0x8062C000`. This verifies the routine's expanded-memory path. It does **not** yet verify automatic Expansion Pak detection or actual framebuffer rendering.

Twenty functions containing privileged CPU operations are excluded from this **translation probe**, without providing host success stubs for them. The probe is intentionally not linked as a game.

The original resident code directly calls 128 distinct addresses outside that candidate resident block. N64Recomp stops at the first unresolved target:

## Research boundaries and review

Other recomps are workflow references only, per the user's instruction. A preliminary cross-ROM SDK matching experiment was discontinued and removed from the maintained project. No inferred binding from it is used. The resident mapping and the two native diagnostic functions come directly from ISS2000.

The resident text limit is a provisional research boundary, based on the return/alignment transition into an apparent RSP boot sequence. It must be confirmed through the game's loader/task paths. It is not sufficient evidence for a complete executable map.

One host-boundary issue found during implementation was using zero-extended addresses with ABI memory macros that expect sign extension. The host now uses `S32` consistently. The buffer-profile integration test failed on the invalid addressing and passed after correction; original guest instructions were not changed.

Independent review covered the initial importer, metadata generator and native entry. Build-receipt fixes and the later buffer-profile extension have regression/process tests; no second independent review is claimed for those later changes.
