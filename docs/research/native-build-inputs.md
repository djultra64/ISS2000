# Native build input identity

Original project work: `djultra64`.

`tools.verify_native_build` is a read-only build prerequisite. It rejects a native
build when the selected ROM profile, original CPU source inventory, section map,
runtime binding manifest, generated metadata or audio translation disagree with
their reviewed receipts. It does not run guest code or launch the game.

The verifier accepts explicit `--revision`, `--generated`, `--metadata`,
`--runtime-symbols` and `--audio` arguments. For example:

```sh
python3 -m tools.verify_native_build \
  --revision iss2000-pal-en-de-rev0 \
  --generated .local/pal-map-bound-01/functions \
  --metadata .local/pal-native-metadata-01 \
  --runtime-symbols config/recomp/iss2000-pal-en-de-rev0/runtime-symbols.json \
  --audio .local/runtime-research-rsp/audio.cpp
```

The selected map's `summary.json` pins every original generated source. All
receipted files must exist and match SHA-256; extra C, header or overlay include
files are rejected. The verifier also rejects source symlinks and inventory paths
that escape the original source directory. The metadata receipt pins
`section-analysis.json`, the current runtime manifest, and exactly the three
metadata implementation files. Their ROM identities must equal the selected
profile. The compact result contains counts and an aggregate input digest.

The three PAL marker aspect derivatives have their own manifest and generated
receipt through `tools.prepare_render_sources`. Verify the original inputs first;
those intentional private derivatives do not alter the original source inventory.
The PAL events override has a separate pinned upstream source and generated
receipt through `tools.prepare_runtime_timing`.

## Original audio translation provenance

`config/recomp/native-build-inputs.json` pins the existing generated source
`.local/runtime-research-rsp/audio.cpp` at SHA-256
`2b8084da8a2d7103385e823a1ce27b30bf8cd101f4e73fe8809d57b0b7c99f09`.
It exports `iss2000_audio_ucode` and was generated by the local pinned
`RSPRecomp` tool using `.local/runtime-research-rsp/audio.toml`, with original RSP
instruction address `0x1080` and explicit reviewed indirect branch targets.
The provenance config records the generator binary digest. Build verification
requires the generated source digest; it does not require the generator binary
to remain installed.

The original US input contributes ROM `0x6C370`, size `0xE28`, mapped at guest
`0x8006B770`. The PAL input contributes ROM `0x6CBF0`, the same size, mapped at
`0x8006BFF0`. The complete 3624-byte original programs are byte-identical with
SHA-256 `412e079b861dcf551dbf27e2372e044abc2686d5a7d9cd878573f29fc0394db1`.
Both exact ROM digests and program locations are recorded in the config.
This is why the original translation is shared across revisions while task
admission uses each revision's own guest address. The original PAL program and
its six RSP segment identities are independently checked by
`.local/pal-runtime-01/audit_runtime.py`; see [PAL runtime research](pal-runtime.md).

Synthetic acceptance and rejection tests are in `tests/test_verify_native_build.py`.
Both current private inputs pass: PAL has 12,172 original receipted files and
US has 12,136. These source receipts establish reproducible build inputs, not
visual gameplay acceptance.
